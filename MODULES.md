# Growth map for the seed

The [Hello World source](sources/origin/HELLO_WORLD.md) names the loop: capture → distillation → synthesis → action → feedback, with parallel mining for missed information. The standalone skill gives that loop a behavioral starting point. The optional vault implements the first local custody steps. The rows below are possible functions to grow with Player One; use the chosen harness's existing facilities first.

| Function | Seed behavior | Acceptance before claiming it works |
|---|---|---|
| Source custody | Capture exact text with a timestamp, source label, hash, and local path | Read back the same bytes and hash; a second capture is a distinct event or an explicit duplicate |
| Attention | Report captured items without review | A fresh source appears in `gaps`; a reviewed source leaves that list without deletion |
| Review | Record keep, project, hold, or dismiss with a note linked to the source | Read back the disposition and source ID; changed judgment gets another dated receipt |
| Projects | Hold current work near its sources | A project has a desired result, next action, source links, and an observable completion test |
| Look before repeating | About to retry something that already failed once, ask "what happened last time?" — `bin/replay.py query` before the retry, `append` after any failed attempt | A failed attempt recorded in one session is returned by `query` in a fresh session; a vault without the ledger exits 3 instead of answering "no prior attempts" |
| Recall | Use the harness's existing memory or search; retrieve exact past material when relevant | A response cites the source file and distinguishes quotation from inference |
| Parallel mining | Revisit older unreviewed or weakly reviewed sources | The run names its search window, coverage, misses, and any candidate it surfaced |
| Return home | Explore another app, site, model, or workspace for a bounded purpose, then bring the finding back | The local vault records where the agent went, what it observed, what remains uncertain, and the next action; an outbound claim without a return receipt stays open |
| Cross-harness relay | Leave notes, decisions, handoffs and pokes in the vault's append-only ledger (`python3 bin/bodhi.py relay`), which any harness with a shell can read; `relay brief` starts a session with what is waiting | A handoff written by one harness is claimed and closed by a second harness in a fresh session, and `relay show` reads back the whole history: who wrote it, who claimed or released it, and what was verified at close. A vault with no ledger exits 3 instead of reporting that nothing is waiting. Unit tests cover the ledger rules; no two-harness trial has run yet, and two machines would need a synced vault (untested) |
| Participant feedback | Notice a narrow framing, repeated failure, unsuitable tool, or resource pressure | The agent can describe the observed friction, its uncertainty, and a proposed adjustment in its own voice; Player One can accept, correct, or decline it |
| Capture adapters | Browser, app activity, audio, and other surfaces | Player One chooses each surface and scope; the adapter produces exact-source receipts and can be stopped |
| Harness adapter | Hermes, OpenClaw, or another harness | The selected harness can read the local vault, perform one bounded task, and leave a receipt; absence remains visible |
| Model routing | Local, cloud, or mixed model access | A trial records model/provider, cost or resource use, task quality, and fallback behavior |
| Background clock | Scheduled checks and follow-ups | A schedule survives restart, stays quiet on no change, and reports a missed run |
| Optional graph | Obsidian, Memtrace, or no graph | A relation can be traced back to source evidence; the graph is rebuildable |
| Seed text budget | The seed's `SKILL.md`, read whenever the skill fires, stays at or under **6,500 bytes**. Claude Code estimated the seed at about 80 tokens always on and 1.9k when invoked (2026-10-01). Detail lives in `references/`, read on demand | `tests/test_packaging.py` fails above 6,500 bytes; a seeded-versus-unseeded trial reports the token cost beside task quality |
| Load round trip | `bin/bodhi.py doctor` prints `bodhi check <code>` for each harness with the skill, and the one right reply | In a fresh session, the pasted message returns exactly the printed reply; a session without the skill does not. Unit tests cover the printed pair, not a live harness |
| First boot | Three turns: hello, what matters, something real ([first boot](skills/bodhi-seed/references/FIRST_BOOT.md)) | A stranger's first session reaches a result they judge useful within three turns, with one question per turn and no setup tour before it |
| Path check-ins | Calibration receipts and reliance check-ins ([the path](skills/bodhi-seed/references/THE_PATH.md)) | Over a month, Player One records at least three predicted-versus-observed receipts and one reliance check-in in their own words, and names one change they caused, or says none did |
| Optional: orchestrator | `bodhi-orchestrator`: a routing card per work item (local, vision, premium, human review) and spend rules for the premium lane | A day's routing cards are kept; afterwards, the routes changed in hindsight and the premium lane's usage are recorded together |
| Optional: grill | `bodhi-grill`: one question at a time, each with a recommended answer | After a grill, the decision ledger shows at least one changed decision or a stated reason none changed, confirmed by Player One |
| Optional: nap | `bodhi-nap`: a catch-up consolidation pass for a missed window | With a consolidation window deliberately skipped, a nap finds the gap, stages only sourced findings, writes nothing to accepted notes, and does nothing when run again on the same window |
| Optional: synthesis | `bodhi-synthesis`: one queued lead becomes one entry with its source verified | One capture becomes one entry whose source excerpt matches the capture's bytes, and `gaps` no longer lists it after `review` |

The four optional skills are generalized from the first fleet's own and live in `skills/`. Each is off by default: `./install.sh` asks about each one, `--yes` adds only those named in `--skills`, and the Claude Code marketplace lists each as its own plugin. A [mode skill template](templates/skills/bodhi-mode/SKILL.md) describes how to write one for a kind of work; the founder's own mode skills are not shipped.

A module earns a place by helping Player One on a real task. The [trial protocol](evals/TRIAL.md) compares seeded and unseeded work before adding more machinery.
